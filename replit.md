# SecureBank Online Banking Application

## Overview

This is a full-stack online banking login application built with React frontend and Express backend. The project simulates a secure banking sign-on page with user authentication functionality. It uses a modern TypeScript-based stack with React for the UI, Express for the API server, and PostgreSQL with Drizzle ORM for data persistence.

## User Preferences

Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend Architecture
- **Framework**: React 18 with TypeScript
- **Routing**: Wouter (lightweight React router)
- **State Management**: TanStack React Query for server state
- **UI Components**: shadcn/ui component library built on Radix UI primitives
- **Styling**: Tailwind CSS with custom theme configuration supporting light/dark modes
- **Form Handling**: React Hook Form with Zod validation
- **Build Tool**: Vite with custom plugins for Replit environment

### Backend Architecture
- **Framework**: Express 5 (latest version)
- **Language**: TypeScript with tsx for development
- **API Pattern**: RESTful endpoints under `/api` prefix
- **Authentication**: Simple username/password validation (currently in-memory storage with demo user)

### Data Storage
- **ORM**: Drizzle ORM with PostgreSQL dialect
- **Schema Location**: `shared/schema.ts` - shared between frontend and backend
- **Current Storage**: In-memory storage class (`MemStorage`) with interface for easy database migration
- **Database Ready**: Drizzle configuration exists for PostgreSQL, schema is defined, awaiting database provisioning

### Project Structure
```
├── client/              # React frontend
│   ├── src/
│   │   ├── components/ui/  # shadcn/ui components
│   │   ├── pages/          # Route components
│   │   ├── hooks/          # Custom React hooks
│   │   └── lib/            # Utilities and query client
├── server/              # Express backend
│   ├── index.ts         # Server entry point
│   ├── routes.ts        # API route definitions
│   ├── storage.ts       # Data access layer
│   └── vite.ts          # Vite dev server integration
├── shared/              # Shared code between client/server
│   └── schema.ts        # Drizzle schema and Zod types
└── migrations/          # Database migrations (generated by drizzle-kit)
```

### Build System
- **Development**: `npm run dev` - runs tsx with Vite middleware for HMR
- **Production Build**: `npm run build` - uses esbuild for server, Vite for client
- **Database Migrations**: `npm run db:push` - pushes schema changes to database

### Key Design Decisions

1. **Shared Schema**: The Drizzle schema in `shared/schema.ts` generates both database types and Zod validation schemas, ensuring type safety across the full stack.

2. **Storage Interface Pattern**: The `IStorage` interface in `server/storage.ts` abstracts data access, making it easy to swap between in-memory storage (current) and database storage.

3. **Component Library**: Using shadcn/ui provides accessible, customizable components without heavy dependencies. Components are copied into the project for full control.

4. **Path Aliases**: TypeScript and Vite configured with `@/` for client code, `@shared/` for shared code, simplifying imports.
